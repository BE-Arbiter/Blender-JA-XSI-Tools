# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Blender add-on importing and exporting Softimage dotXSI 3.0 skeletal animations (`.xsi`, the text
format 3ds Max writes and Raven's Carcass compiles into Jedi Academy `.gla` files) as NLA strips. It
is meant to be used with the Blender Jedi Academy Plugin Suite (`jediacademy` add-on,
`../Blender-Jedi-Academy-Tools`), which owns `.gla`/`animation.cfg` I/O; this add-on only mirrors its
scene conventions (armature `skeleton_root`, NLA layout, `action.g2_sequence_prop`), it never imports it.

The installed module name is `io_scene_dotXsi3` (folder name inside the release zip), kept for
compatibility with installs predating this repo.

## Commands

- `make` — builds `build/io_scene_dotXsi3.zip` (installable add-on) and `build/ja_xsi_tools_doc.pdf`.
- `make pep8` / `make format` — pycodestyle check (what CI runs) / autopep8 fix, config in `.pep8`.
- Tests: `.claude/skills/blender-tests/run_blender_tests.sh 4.1 5.2` (podman), or a local Blender:
  `blender --background --factory-startup --python-exit-code 1 --python tests/run_tests.py`.
- CI (`.github/workflows/ci.yml`) mirrors the Jedi Academy suite's: `smoke-test` (Blender 4.1 and 5.2),
  `typecheck`, `pep8` on PRs, tags and the daily schedule; `nightly` and `release` publish the zip and
  manual. See that repo's CLAUDE.md for the reasoning behind the nightly/attempted-tag mechanics.

## Writing comments, commit messages, PR descriptions, and issues

Keep all four succinct: state the fact/change, skip restating what the diff already shows. A comment
should carry the one thing the code alone doesn't (a non-obvious *why*), not a narration of the *what*.

## Architecture

- `dotxsi.py` — standard-library-only parser: tokenizer to a generic `Block` tree, then `Scene`/`Model`/
  `FCurve` views (SRT, base pose, curves sampled linearly). Testable outside Blender.
- `xsi3_blender_importer.py` — builds the armature (if needed) and bakes the animation into actions and
  NLA strips.
- `xsi3_blender_exporter.py` — samples the selected strips' actions directly from their FCurves (no
  `frame_set`, no depsgraph) and writes the file. Exact inverse of the importer's conversions.
- `__init__.py` — operators (`import_anim.dotxsi3`, `export_anim.dotxsi3`), dialogs, menu entries.

### File conventions (verified against Raven's `_humanoid.gla` — don't change without re-checking)

- `SI_Transform SRT-` is local to the parent, `BASEPOSE-` is world space. Euler XYZ in degrees,
  local = T @ R @ S. Bone scale is dropped (Ghoul 2 has none; CAT face bones are scaled 1.087).
- Files are Y-up: `(x, y, z) -> (x, -z, y)`; `_humanoid` scale is 0.64. Ghoul 2 bones point along X,
  Blender's along Y: `gla_to_blender_bone` is the same axis swap as the jediacademy add-on's
  `JAG2Math.GLABoneRotToBlender`, so both add-ons agree on rest poses.
- Carcass applies the model origin: every `_humanoid.gla` frame has `model_root` at `(0, 0, -24)`, the
  base pose at 0. The importer adds it (`origin_offset`), the exporter removes it.
- Carcass drops an `_always_` suffix: `face_always_` in the file is `face` in the `.gla`.
- Animation is transferred as world-space deltas from the base pose applied to each bone's own rest
  pose, so an armature with different rest orientations (jediacademy's skeleton fixes) still works.
- Blender iterates bones hierarchically, not in `_humanoid.gla` order: `.gla` export must use the
  "gla reference" option for bone indices to match.

### Blender version support

`bl_info["blender"]` is 4.1. Blender 4.4 introduced slotted actions and 5.0 removed `Action.fcurves`:
every FCurve access goes through a helper with both paths (`get_fcurves`, `strip_fcurves`,
`hasattr(action, "slots")`/`"layers"`). CI tests the 4.1 and 5.2 boundaries.

## Testing

`tests/run_tests.py` runs headless cases against `tests/testdata/simpleskel.xsi`, a synthetic file
generated by `tests/tools/generate_test_xsi.py` in 3ds Max's layout (`_humanoid` bone names plus
`skeleton_root`/`mesh_root`/`_eff`/`face_always_` extras). Real game or community files are not
committed: they're proprietary or third-party (keep local copies in the git-ignored `.proprietary/`).

Comparisons are logical, not byte-for-byte: parse the files back with `dotxsi` and compare world
matrices (rotation ignoring scale, with tolerances), or compare evaluated pose matrices in Blender.

## Releases

Same process as the Jedi Academy suite (see the `release` skill): SemVer in `bl_info["version"]`;
user-facing changes add a bullet under `\subsection*{next version}` in `ja_xsi_tools_doc.tex`'s
Changelog (not for internal changes, nor for bugs that never reached `master`); the release PR renames
it to the version and its commit message is the GitHub Release body; tag the version-bump commit, not
the merge commit, with `.claude/skills/release/tag_release.sh`. Dropping a Blender version is a major bump.
